# UI 状态巡检与 TV 窗口验收

2026-10-25，独立工作区 `v3`。本轮重点检查播放器七种状态、播放选择面板，以及首页、频道、收藏、节目单、列表管理的空数据与错误入口。

## 修正的问题

| 问题 | 修正 |
| --- | --- |
| 播放失败、格式不支持、纯音频沿用列表页的大卡片，内容堆在顶部 | 使用播放器专用的居中内容区，无外层背景卡片；窄屏可滚动，操作随内容换行 |
| 失败后仍可出现播放控制栏、LIVE 与重复重试，甚至残留播放和小窗交接 | 统一终止状态，暂停后端并取消恢复计时；收起已有控制栏，失败页直接提供重试、换源、换台与诊断 |
| TV 失败页焦点留在播放器，确认键无效；左右方向键还会误触原来的快捷切台 | 失败页渲染后明确聚焦重试按钮；方向键交给按钮焦点导航 |
| 来源、画质、音轨、睡眠面板为固定窄按钮与灰色通栏，部分文字只有 13px | 统一为主题面板和全宽按钮，按设备密度调整字号与点击区域；增加标题与关闭按钮，内容过长时内部滚动 |
| 来源编号在重建后继续递增 | 使用去重后的固定索引生成编号 |
| 频道选择器在浅色选中背景上仍用白字，TV 字号较小，大字号行高固定 | 修正选中态文字对比度，采用设备字号，并按文字比例计算行高与初始滚动位置 |
| 组件验收页没有真正的视频区域约束，错误态也展示正常播放条 | 增加 16:9 预览区域，只在播放/暂停时展示正常控制条 |

列表、收藏、节目单和远程连接的空/错误状态仍位于各自内容区；刷新失败会保留已有频道或节目缓存，没有发现应套用播放器浮层的场景。本轮并非对所有设置子页进行逐像素审查。

## 验证

- 主应用测试：207 项通过。
- UI 包测试：21 项通过，含四种设备、双倍文字、居中反馈、操作可达性。
- 组件目录：四个视口、七个分类通过。
- 选择面板：手机窄屏与双倍文字、iPad、桌面、960×540 TV，关闭、来源编号及频道选择均通过。
- iPad 原生：真实 HTTP 404 流触发完整失败流程，重试会重新请求，换源和换台面板可打开，失败退出不进入小窗。
- Android TV 原生：同上；额外断言重试按钮取得焦点，左右键不误开面板，确认键实际触发重试。

原生用例为 `integration_test/player_failure_test.dart`，不清理已有列表和收藏。使用 `flutter drive --keep-app-running`，完成后构建正常 `lib/main.dart` 入口覆盖安装。iOS 覆盖安装若更换文档容器，应更新专用 QA 列表的本地文件 URI。

Android 使用日志 `QA_FAILURE_STAGE failed` / `sources` 作为宿主 `adb exec-out screencap -p` 截图时机，避免测试框架的 Flutter ImageView 截图转换影响有窗口模拟器渲染。驱动已关闭重复保存整份截图 base64 的通信日志，图像与 JSON 报告仍单独保存。
