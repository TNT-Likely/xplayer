# iPad 声音与缓冲反馈

2026-10-25，独立工作区 `v3`。

连接与缓冲状态改为画面中央的小转圈，移除整块提示背景、说明文案及操作按钮。缓冲时继续保留视频画面，浮层不拦截播放器点击；返回和实际播放失败后的重试入口保留。减少动态效果时显示静态进度环。

[iPad 正常应用的连接状态截图](screenshots/player-loading-ipad.png)。组件包 17 项测试通过，包含转圈位置、画面与点击保留的回归；本轮变更的静态分析无问题。iOS / Android 正常入口已重新构建并覆盖安装到专用手机、iPad、TV，测试播放列表保留。

声音排查确认：播放时系统混音存在非静音 PCM，停止 iPad 应用后静音基线归零。用户可听到 Mac 直接播放的短提示音，但听不到模拟器节目。模拟器的 `I/O → Audio Output` 中勾选的 System 仍指向显示器，而 CoreAudio 查询到的媒体和系统默认设备均为外接音箱；手动指定实际音箱后，用户确认正常版 iPad 应用的 CCTV-3 声音恢复。现象支持模拟器默认路由未更新，尚未确认 Simulator 内部具体原因；无需更改应用音量或播放引擎。

原生补测包含 H.264/AAC FLV、H.264/MP3 FLV 与真实 CCTV-3 HLS（H.264/MP2，1920×1080），三项均使用 MediaKitBackend，取得首帧、播放位置推进及 AudioUnit 输出。系统 PCM 采样与用户听感分别记录，音轨存在不能单独视作扬声器验收通过。最终正常应用播放 CCTV-3 的 12 秒系统采样 RMS 为约 -25.97 dBFS，峰值 0.399；未采集或保存音频内容。

后续复测可在 `integration_test/live_sources_test.dart` 使用 `QA_AUDIO_HOLD_SECONDS` 留出系统采样窗口，控制台的 `QA_AUDIO_READY` 表示窗口开始。短效地址、局域网配置和原始日志仅保存在忽略目录。
