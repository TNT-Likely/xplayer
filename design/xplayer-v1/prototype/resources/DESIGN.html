# XPlayer 设计规范 v1

## 决策与来源

确认日期：2026-10-25。用户选择 A「静夜」作为主方向，并要求保留 B「留白」与 C「信号」。视觉源为本目录的 HTML 交互稿，基线源码提交为 `f85733a91d12fc4eee85fac712cca16d11c4e6c3`。本次沉淀不修改现有 Flutter 的 AppTokens。

XPlayer 的主要任务是找频道、看直播、查看 EPG、收藏及管理 M3U 播放列表。首页的节目大图服务于正在播出的频道，不表示产品拥有点播片库或托管视频。

## 三条方向

| 方向 | 状态 | 视觉与编排 |
| --- | --- | --- |
| A · 静夜 / Nocturne | 主方案 | 深松绿背景、薄荷操作色、柔和圆角；大图与当前节目并置，频道卡片保持呼吸感 |
| B · 留白 / Paper | 保留备选 | 暖白背景、钴蓝操作色、小圆角；图文分栏，频道信息采用杂志式层级 |
| C · 信号 / Signal | 保留备选 | 石墨背景、琥珀操作色、接近直角；紧凑的横向频道卡片，强调直播状态 |

三套语义色值均从 CSS 抽取，见 `tokens/xplayer.tokens.json`。以变量文件为精确来源，不从截图吸色。

## 四端共同语言

颜色角色、图标语义、频道/节目命名、直播状态、节目进度、收藏反馈和信息结构保持一致。导航形态、字号、信息密度、触控范围和播放器编排按设备适配。

“约 70% 共同语言 / 30% 场景适配”是前期设计取舍的说明，不是代码复用率目标。实现应围绕内容、可访问性和平台约束决定复用边界。

| 设备 | 基准视口 | 导航 | 浏览与播放 |
| --- | --- | --- | --- |
| 手机 | 390 × 844 | 底部五项导航 | 单列纵向浏览；频道双列；独立播放器；迷你播放器位于底栏上方 |
| iPad | 1194 × 834 | 82px 窄侧栏 | 横屏浏览；播放保留右侧选台栏；窄窗口减少列数 |
| 桌面 | 1440 × 960 | 216px 完整侧栏 | 即时搜索、多列频道、完整 EPG；播放器旁边选台；右下角迷你播放器 |
| TV | 1920 × 1080 | 顶部导航 | 大字号与留白；空间方向键导航；可见的焦点框；Esc 逐层返回 |

基准视口用于评审，不等于固定运行尺寸。实现时优先依据可用空间和输入方式，不仅根据设备名称判断布局。

## A 方案的视觉基础

| 语义 | CSS 变量 | 色值 |
| --- | --- | --- |
| 页面背景 | `--bg` | `#0f1915` |
| 内容表面 | `--surface` | `#14211b` |
| 抬升表面 | `--raised` | `#1b2a22` |
| 边界 | `--border` | `#29382e` |
| 主文字 | `--fg` | `#edf2e9` |
| 次要文字 | `--muted` | `#8d9c8d` |
| 辅助文字 | `--quiet` | `#627566` |
| 强调色 | `--accent` | `#b5e6bb` |
| 强调色上的文字 | `--accent-ink` | `#17371e` |

辅助色适合分隔和低优先级说明；实际产品中的重要标签、EPG 时间和可点击信息应检查所在背景的对比度，避免直接套用展示稿中较小的辅助字号。

字体：Latin 优先 Inter，中文由系统 PingFang SC / Microsoft YaHei 等回退。Figma 共享字号样式使用 Noto Sans SC，英文衬线替代映射另行记录。跨渲染器的字面宽度与行高可能有轻微差异。

间距基线：4、8、12、16、20、24、28、32、36、44、48、60、84。A 的通用面板圆角为 16px，频道卡片 12px；B/C 按各自变量与局部样式保留。精确组件值以 HTML 计算样式为准。

## 布局与内容规则

- 首页：当前列表与搜索 → 当前频道节目 → 分组与频道 → 最近播放。
- 频道卡片：节目画面、直播/清晰度标记、频道身份、收藏、当前节目及时间进度。节目画面未知时，产品应回退为频道标识或中性缩略图。
- EPG：频道列与时间轴相互对应；当前时间线按统一时间比例定位；未来节目详情应说明尚未开播。
- 长文本：频道名优先保留，辅助信息可截断；核心操作标签不截断。节目单允许横向滚动。
- 空状态：解释原因，提供查看全部、清除筛选或添加列表的下一步。
- A 已补充加载、网络错误、源失效与无 EPG 等代表设计；完整判定、恢复与组合规则见 EDGE-CASES.md。原型的“演示成功”反馈须在实现阶段替换为真实服务结果。

## 输入与动效

手机主要按钮、分组和图标采用 44px 起的操作区域，密集卡片中的文字使用整卡播放入口补充触达。TV 焦点使用 4px 强调色描边和 5px 外偏移，避免仅靠颜色区分状态。确认使用 Enter，返回使用 Esc。桌面 `/` 搜索，播放器中 Space 切换播放状态。

常用反馈约 150–200ms，节目图片轻微缩放约 500ms；降低动态效果时禁用非必要过渡。焦点、收藏和播放状态应可被辅助技术识别。

## 实现交接

推荐共享频道卡片数据、播放控制语义和颜色角色；布局层拆分手机底栏、iPad 窄侧栏、桌面侧栏、TV 顶栏。播放器采用共同控制模型，再按设备编排控件。保留用户主题色能力时，应通过语义角色映射处理，避免直接将主色用于所有文字与焦点。

现有 Flutter Token 与新设计存在差异。本资源包记录目标设计，不包含迁移实现或 Code Connect 绑定。
