01　如何拆包

包负责内容
xplayer_player播放 API、源和请求头、HLS、策略、状态、音频会话、libmpv 后端。
libmpv_xplayer固定原生资产、SHA-256、Darwin 视频桥接、模拟器 AudioUnit、Android EGL；Linux 接系统 libmpv。

主应用使用版本依赖，仓库开发通过 Dart workspace 解析本地包。外部分发验证故意改变两个包的目录，防止依赖相邻源码。独立示例覆盖 Android、iOS / iPadOS、macOS、Windows、Linux，不引用主应用的数据库和 UI。

Android 专用 ExoPlayer SurfaceView、电视界面、小窗、用户设置继续由主应用负责。独立示例直接测试核心 libmpv，不能把主应用的回退成功算成核心本身成功。

02　独立接入暴露并修复的问题

Darwin：编译成功，视频通道却为空

上游按旧二进制包名扫描锁文件；改名后会编译空实现。新原生包接管固定版本的 Swift 视频纹理桥接并自行注册，macOS、iPhone、iPad 的实际播放矩阵均通过。CI 增加仓库外宿主运行检查，防止只凭构建成功放行。

Android：HLS fMP4 首次切换 Surface 后直接到结尾

原生内部 seek 失败会过早耗尽流。对已知时长、尚未正常推进的 HLS，使用已建立的 Surface 重开 demuxer，最多一次。正常播放、主动 seek、短文件与未知时长直播不触发此恢复；不关闭全部 HLS 的 seek 功能。

初次独立矩阵曾为 71/72，针对修复重测 2/2，再跑完整手机、TV 矩阵各 72/72。手机完整矩阵记录了两种模式的单次恢复。相关上游问题：fMP4 HLS seek、Android Surface / seek。

依赖下限与启动探测

最低依赖测试发现旧 win32 / archive 使用了新 Dart 已删除的 API，已加入兼容下限并通过复测。EGL 探测合并并发请求、缓存失败和超时结果，避免多播放器反复等待失效驱动；保留不可变的探测证据。

05　稳定发布前继续补齐

  1. Windows / Linux 实际运行：先执行新增 CI，再覆盖桌面视频输出、音频设备与休眠恢复。
  2. 真实 Android TV / iOS 设备：旧系统、不同 GPU、遥控器生命周期、横竖屏、前后台、音轨切换、蓝牙与 HDMI。
  3. 长时间和故障验收：30 分钟 / 2 小时播放、频繁切台、断网重连、源切换、资源释放与内存趋势。
  4. 原生库迭代：继续保留完整构建，固定版本和散列；更新旧 Android / Darwin 库并验证能否取消已证实的启动兼容分支。
  5. 真实 hosted 安装：先发布原生包，再发布 API 包，用全新宿主验证安装、构建、关键播放，之后再提升稳定版。

现在不需要另建仓库。两个包共仓维护能把 API、原生库、示例和测试作为一组升级；后续有独立维护者、不同发布周期或多个宿主后再评估分仓。
